# SC004 R5.8 — QA improvements m1–m3

Base: 508b00e19326f176d3c92df5d6341fdafd27fb2d. Local QA-only patch. This is not remediation of BLOCKER-1; that blocker has not been detailed or resolved by this work.

m1 adds a separate R58 named-grant mutation: baseline PASS/DENY; temporarily grant EXECUTE on public.sc004_assignment_lifecycle() to service_role; require FAIL/ALLOW while PUBLIC remains denied; print the intentional failure; ROLLBACK; require PASS/DENY and absence of the mutated result. Only baseline and rollback remain in normal results. This R58 group is not added to qa_mutation_results and does not change the 22 frozen C/D groups or M20 INVALID. The exact R58 normal-result gate changes from 10 to 13: two retained m1 rows and one m2 reachability row. Its all-PASS condition stays unchanged.

m2 reports MEMBER reachability separately from USAGE inheritance and checks EXECUTE of each reachable role against both protected functions. A role may have no immediately effective EXECUTE yet be able to reach it with SET ROLE in PostgreSQL 15. A QA-only self-test creates NOLOGIN roles (one NOINHERIT), a membership between those fixture roles, and a harmless QA-schema function. It proves MEMBER=true, USAGE=false, effective EXECUTE=false, potential EXECUTE=true, then rolls the entire fixture subtransaction back and verifies no roles/function remain. The self-test is archived outside normal results. No production owner, membership or persistent grant changes. Existing production roles are not granted new memberships.

m3 removes the fixed one-second wait. The passwordless probe can run at most ten times with the existing five-second libpq connection timeout; 0.1-second spacing occurs only between retries. Only an accepted passwordless connection (old trust rule still active) is retried. Unrelated failures abort immediately, and failure to observe the intended no-password denial by the tenth attempt aborts. The required no-password/wrong-password harness invocation lines remain exact. The wrong-password probe is still single-shot, and the valid password/dblink checks still follow. No password, credential conninfo or raw captured diagnostic is emitted. The existing outer runner timeout remains unchanged.

Frozen: all 50 migrations and their exact inventory, original A/B and C/D files, academic contracts, RLS, trigger definitions, runner session order and existing workflows. Runtime remains NOT RUN; mutation detection, NOINHERIT catalog semantics and active HBA propagation still need independent validation on disposable Ubuntu/PostgreSQL.
